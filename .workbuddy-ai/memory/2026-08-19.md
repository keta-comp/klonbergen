## Edge Function 500 "supabaseUrl is required" — root cause + BULLETPROOF fix
User kept getting `HTTP 500 / sb-error-code: EDGE_FUNCTION_ERROR` on `create-hall-admin` (curl body `{"error":"supabaseUrl is required."}`; browser net log confirmed same 500 with valid super-admin auth token). 
- **KEY FINDING:** Supabase auto-injects `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY` into every Edge Function, and the **Dashboard BLOCKS manual secrets starting with `SUPABASE_`** ("Name must not start with the SUPABASE_ prefix"). So the user CANNOT (and never needs to) add those names manually.
- **Real problem:** the deployed function was NOT receiving the auto-injected env vars (deploy via Dashboard inline paste apparently didn't link the function to the project env). That's why `Deno.env.get("SUPABASE_URL")` returns undefined → `createClient` throws "supabaseUrl is required".
- **Fix applied to all 3 functions** (`create-hall-admin`, `archive-weddings`, `build-wedding-zip`): replaced the strict `Deno.env.get("SUPABASE_URL")!` / `SUPABASE_SERVICE_ROLE_KEY`!` with a bulletproof fallback:
  ```ts
  const url = Deno.env.get("SUPABASE_URL") ?? Deno.env.get("SB_PROJECT_URL") ?? "https://vbikhnzwnsfddgjzwuge.supabase.co";
  const serviceKey = Deno.env.get("SUPABASE_SERVICE_ROLE_KEY") ?? Deno.env.get("SB_SERVICE_ROLE_KEY");
  if (!serviceKey) return json({ error: "SB_SERVICE_ROLE_KEY secret topilmadi" }, 500);
  ```
  The URL is PUBLIC (ships in frontend bundle) so hardcoding it as fallback is safe; service role key is read from non-reserved `SB_SERVICE_ROLE_KEY` that the user CAN set manually in Dashboard → Edge Functions → Secrets.
- **User action required (Dashboard only):** (1) set secret `SB_SERVICE_ROLE_KEY` = the service_role JWT; (2) replace the 3 env lines in the function code with the fallback block above; (3) Deploy. After this the function no longer depends on Supabase auto-injection.
